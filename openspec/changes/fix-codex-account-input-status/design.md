# 方案

## 改动与不变量

沿用 `codex_chatgpt_request_compat_value`：完成顶层白名单复制后，对克隆对象 `next.input` 的数组对象逐项 `remove("status")`，不递归、不按索引硬编码、不修改源对象。补充函数注释；生产改动限制在此函数。

第 2 轮沿用同一个循环：仅当对象 `type == "reasoning"` 且已存在 `id`，其值不是以 `rs` 开头的字符串时，`remove("id")`。前缀判断严格按上游错误的 `rs`，不额外限制为 `rs_`。不改其他类型的 ID、不新增 ID、不修改 `call_id`、summary、encrypted_content 或嵌套内容。省略非法可选 ID 比伪造一个服务端已存在的 ID 更保守；但只修格式，不能将外部密文变成账号可解密数据。

账号检测及 `/responses` 路径判断均沿用现状，普通 API 不新增调用。除下述不合规 reasoning ID 外，保留所有其他字段与现有顶层兼容规则。固定规范化不引入时间戳或随机值；不改 `prompt_cache_key`、`previous_response_id`，但不保证跨后端缓存共享或实际命中。

不选择修改 Pi、清空历史或报错后重试：AIO 已有集中兼容接缝，边界处一次处理更小且稳定。

## 验证与回滚

AC-001/002：混合历史输入回归，断言除直属 `status` 外逐项完全一致、源对象不变及幂等性。
AC-003：字符串、对象、null、缺失 input 与非对象数组元素不新增变换；调用点审查确认仅账号分支使用。
AC-004：新增单个 reasoning ID 回归，表格覆盖非法字符串及 null/数字/布尔/对象/数组、合法 `rs` 前缀和缺失 ID；构造第 47 项与工具配对，断言只有直属非法 reasoning ID 与 status 被省略，嵌套业务、其他 ID、源对象、缓存标识及重复处理结果保持稳定。

先补测试观察 RED，再实现并观察 GREEN。首选窄范围 Rust 测试，限制并发；若 Tauri 全包重编译受资源限制，使用临时 `rustc --test` harness 导入真实源模块运行相同兼容测试，不复制生产函数，明确未覆盖的完整构建。运行定点 rustfmt 与 `git diff --check`。前端未改不跑前端全量构建。

实施后授权一次只读独立复核，覆盖代码、测试与本任务产物；验收留给用户。回滚只需撤销本函数新增循环与对应测试，无数据迁移。

## 未验证边界

真实失败请求具体 item 类型、真实账号继续对话与 cached token 变化未在线验证；不采集凭据或发送用户会话。
第 2 轮具体错误的服务端 rs 前缀要求已由截图确认，reasoning 类型由此推断并在合成历史中复现；未捕获原始 input[46]。新增省略 ID 不保证解决跨后端密文解密、服务端历史配对或其他字段差异；保留密文与全部关联标识，不静默丢弃历史。
