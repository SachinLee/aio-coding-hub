# 模型级供应商路由禁用

## 目标与授权

用户已确认方案并要求实施：模型 A 可单独禁用供应商 1，而供应商 1 的其他模型、模型 A 的其他供应商均不受影响。独立于 `configurable-provider-selection-strategy`，不修改该功能的行为和交付记录。

风险等级：critical（SQLite 持久化迁移、IPC 与网关跨层行为）。本任务在主会话实施；尚无独立复核证据，不宣称验证完成。

## 验收标准

- [ ] AC-001：按 `(cli_key, model_id, provider_id)` 隔离开关；默认启用，重启后保存。
- [ ] AC-002：模型目录显示每条供应商路由的开关；禁用不隐藏目录记录，可恢复；保存失败回滚并提示。
- [ ] AC-003：新请求的候选集排除禁用路由；同供应商其他模型、同模型其他供应商及其他 CLI 不受影响。
- [ ] AC-004：显式指定禁用路由时返回明确的模型路由不可用错误，不静默换供应商；全部路由禁用时不发往上游。
- [ ] AC-005：刷新模型目录不覆盖禁用配置；模型暂时消失后保留配置，删除供应商时清理其路由配置。
- [ ] AC-006：Codex 已验证的 Responses WebSocket 续接可保留原供应商；不能把已有 `previous_response_id` 交给另一供应商；下一次独立选路遵守开关。
- [ ] AC-007：配置保存后新请求即时生效，在途请求不被切换；数据库迁移、IPC 类型和前端 service 保持一致。

## 约束

用户明确要求不运行单元测试（内存不足）。本轮也不启动重型编译；只运行轻量格式、差异检查，未执行的检查标记 `NOT RUN`。测试文件可补充但不得声称已运行。未经用户验收不归档。
